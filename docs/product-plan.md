# Product plan
Derived from a twelve-agent research pass over the open-source spreadsheet
landscape, the Microsoft Open Specifications, and a decade of publicly recorded
Excel feature requests. This is the plan the code is being built against.

## The five improvements we are building in

Ranked by how unanimous and how long-standing the underlying complaint is.
Two of them cannot be retrofitted, which is why they exist in the core already
rather than on a roadmap.

### 1. Undo that survives macros, imports and closing the app

**Evidence.** Microsoft's own docs: any VBA write to a workbook clears the entire undo stack, and Application.Undo 'undoes only the last action taken by the user before running the macro, must be the first line in the macro, and cannot be used to undo Visual Basic commands.' The only sanctioned mitigation is Application.OnUndo, which requires the macro author to hand-write an inverse procedure. Compounding it: the stack is APPLICATION-GLOBAL across every open workbook (Microsoft Q&A threads titled 'Major Bug' confirm this is by design, workaround = a separate Excel process per file), depth defaults to ~16–100 via a registry key Microsoft advises against raising because the history is held in RAM, sheet delete/rename/insert are not undoable at all, and the whole stack dies on close. Univer's OSS engine — the best permissive prior art — defaults to 50 entries and its IUndoRedoItem carries no label, timestamp, or affected range.

**What we build.** Every mutation is a Command carrying a computed inverse Mutation, on a per-DOCUMENT, byte-bounded (~256 MB resident, disk-spilled), persisted op-log. Because the VBA host and the scripting host are just other writers on the same command bus, a macro runs inside one nestable transaction that collapses to ONE labelled undo entry — and auto-rolls-back on an unhandled macro error. Copy-on-write CellBlocks make a 1M-cell paste undo as a list of (col, blockIndex, previousBlockRef): O(1) per touched block, zero copying. Ships with a labelled history panel (source icon, timestamp, hover-to-flash affected ranges, batch-undo-to-entry, macro transactions expandable into their inner steps — which doubles as a macro debugger), surviving close, reopen and crash. Structural ops are ordinary commands, so delete-sheet is undoable. Marketing line: 'undo a macro' — something Excel has not been able to do in thirty years.

**Difficulty.** Medium if designed in week one; effectively a rewrite if retrofitted. Non-negotiable rule: no UI code ever touches the model directly. This one substrate also delivers improvements #2, #3 and #4 below, which is why it is first.

### 2. Never mangle my data — lossless entry, paste and import

**Evidence.** The most documented Excel defect in the scientific literature. Ziemann/Eren/El-Osta (Genome Biology 2016) scanned 35,175 supplementary files from 3,597 papers and found erroneous gene-name→date conversions in ~20% of papers with gene lists; Abeysooriya et al. (PLOS Comp Bio 2021) rescanned >10,000 papers from 2014–2020 and found 30.9% affected — it got WORSE. The HUGO Gene Nomenclature Committee ultimately renamed real human genes (MARCH1→MARCHF1, SEPT1→SEPTIN1) to work around a spreadsheet. Microsoft's fix arrived only in October 2023 as File > Options > Data > Automatic Data Conversion — per-USER, not per-file, so it does not travel with the workbook, and it does not cover every coercion path (paste, Power Query, CSV open). Separately, 16+ digit IDs are still silently rounded to 15 significant digits.

**What we build.** Every cell stores the user's literal input string alongside the inferred typed value, making type inference a reversible DISPLAY decision rather than a destructive parse. Per-column type locks persist IN THE FILE (a custom OPC part Excel ignores gracefully), not in app settings. CSV/paste import defaults to text with a per-column preview and a blocking 'N cells would change meaning' diff before commit, plus a non-blocking review chip afterwards ('412 cells interpreted as dates — review / revert all'). Exact-precision integer storage so a 19-digit order number or an IBAN survives verbatim. Critical layering rule: entry is non-destructive while formula EVALUATION stays bug-compatible with Excel's coercion rules — those are two different layers and conflating them produces subtly wrong numbers in financial models, which is the worst possible failure.

**Difficulty.** Medium, and only if the literal-string field is in the cell model from day one. Cheap to build, impossible to retrofit, and it comes with the two most cited spreadsheet-failure stories in existence as free, verifiable marketing.

### 3. Never silently lose anything — total round-trip preservation and no guessed ranges

**Evidence.** Two independent bodies of evidence. Library side: ExcelJS issue #141 ('Chart support') has been open since 26 June 2016, and #2607 documents the worse failure — 'ExcelJS removes the charts when reading the file and converting it into a workbook', so template→edit→save silently destroys every chart; openpyxl's own docs concede 'images and charts will be lost from existing files if they are opened and saved with the same name.' Application side: Excel guesses the extent of your data and stops at the first fully blank column, so a single-column sort silently decouples rows with no error — the canonical r/excel support question. And Public Health England lost 15,841 positive COVID-19 test results (25 Sep – 2 Oct 2020) because an ingestion pipeline used legacy .xls, which caps at 65,536 rows and dropped every record past the ceiling with no error and no warning.

**What we build.** A PackageStore 'part vault' retains every OPC part AND every unrecognized XML element inside parts we do model (extLst, mc:AlternateContent, x14/x15/xr extensions), tagged with its schema-sequence position and re-emitted in strict CT_Worksheet order. CI asserts the zip entry SET is unchanged and every retained part is XML-semantically equal after open→no-op→save. On the app side: contiguous data regions are first-class Table objects so sorts always move whole records and a row-decoupling single-column sort is not expressible without an explicit override; every destructive command runs a cheap dry-run and shows 'N cells will be overwritten' before executing; imports NEVER truncate — they stream into the columnar store and page the view. The single exception to preservation is calcChain.xml, which we deliberately DELETE along with its relationship and Content_Types override while setting calcPr/@fullCalcOnLoad=1, because a stale calcChain is its own family of repair prompts.

**Difficulty.** Low-to-medium and mostly week-one architecture — the vault is a few hundred lines. It converts roughly 60% of the unbuilt feature list from 'data loss' into 'view-only, round-trips fine', which is the difference between a demo and a product people trust with real files.

### 4. Local version history, semantic diff and three-way merge — with no cloud

**Evidence.** File > Info > Version History is greyed out unless the file lives on OneDrive/SharePoint with AutoSave on and a suitable licence; a locally-saved workbook has no history at all beyond AutoRecover scratch files. Spreadsheet Compare — the only first-party diff tool — ships only with Microsoft 365 Apps for enterprise, and Microsoft Q&A carries 2024–2025 threads from paying subscribers who cannot find it; Microsoft announced retirement of its sibling Database Compare for June 2026. There is no merge capability at all. Meanwhile the cloud path users are pushed toward generates its own steady complaint stream: AutoSave overwriting the original instead of prompting Save As, duplicate files appearing in OneDrive\Documents, and reverting to an older synced version.

**What we build.** This is the offline-first thesis stated as a feature. Every save plus a timer commits a content-addressed snapshot to a sidecar store beside the file (.mirrorz/ SQLite pack), with named checkpoints, restore and export-as-copy — zero cloud, zero account. Diff is SEMANTIC, not byte-level: cell values, formulas, formats and structural edits, with row/column insertion detection so an inserted row reports as one change rather than 10,000, rendered as 'Sheet2!B4: =SUM(A1:A9) → =SUM(A1:A10)'. Three-way merge for the real-world case of two colleagues emailing back edited copies. A stable semantic text export lets real VCS diff workbooks. Because we already have the op-log from #1, our diff knows INTENT, not just end state — an advantage no file-comparison tool has. And unlike Excel's AutoSave, the user's file on disk is never mutated without an explicit save.

**Difficulty.** Medium-high. Snapshotting is easy; structural-change detection is the genuine algorithm risk and merge-conflict UX is hard. Storage needs dedup and compaction. This is the flagship paid feature and Excel structurally cannot follow, because its history is architecturally tied to OneDrive.

### 5. Formula debugging: a real editor, live evaluation, and one-click root cause

**Evidence.** The formula bar is a single-line control by default. 'Evaluate Formula' is a modal dialog you cannot leave open while editing. Trace Precedents draws transient arrows that do not survive edits and handle cross-workbook references poorly. The community's actual debugger is selecting a fragment and pressing F9 — which PERMANENTLY DESTROYS the formula if you then press Enter. The decisive evidence is that Microsoft shipped the fix as an ADD-IN rather than in the product: the Advanced Formula Environment, later folded into Excel Labs (github.com/microsoft/Excel-Labs, MIT), providing IntelliSense, inline errors, auto-formatting, code collapse, comments and indentation. When a Garage add-in is the state of the art, the in-product experience is inadequate by definition.

**What we build.** Ship the AFE experience as the DEFAULT editor and then go past it: an always-available multi-line editor with syntax highlighting, auto-indent, preserved whitespace on save (Excel's grammar ignores it inconsistently; we round-trip it), and hover definitions for named ranges and LAMBDAs. A live evaluation gutter showing each argument's value as you type. A formula inspector with an expandable AST tree where every node shows its evaluated value and the exact cells it read, click-to-jump. ROOT-CAUSE SEARCH: given an error cell, walk the dependency DAG and name the originating cell(s) in one click — no arrows to chase. And 'why did this value change?' answered directly from the op-log. Persistent cross-file precedent/dependent panels rather than decoration.

**Difficulty.** Medium. The dependency DAG already exists for recalculation, so this is largely a UI over an instrumented 'explaining' evaluation mode — kept strictly separate from the fast path and run only for the inspected cell. Pairs naturally with #4 in the same release train to form the 'what changed and why is it broken' pillar.

## Delivery phases

- PHASE 0 — GUARDRAILS (week 1, before any feature). Rename is already done in-repo and must hold: the product is MIRRORZ Sheets, never 'MIRRORZ-Excel' in any shipped name, domain, store listing or social handle — Microsoft's guidelines prohibit brand assets 'in the name of your business, product, service, app, domain name, social media account', and selling a directly competing spreadsheet is the worst posture in a confusion analysis; Excel appears only adjectivally ('opens .xlsx files', 'compatible with Excel formats') with a standing non-affiliation disclaimer. Land: (a) a CI license scanner with a hard-fail denylist, before the dependency tree grows; (b) docs/legal/IP-POLICY.md — implement only from OSP-covered specs and permissive sources, never decompile any Microsoft binary, reading copyleft for architecture is fine and copying a line is a firing-level offence, and every non-obvious format behaviour carries a spec citation in a code comment; (c) the part vault in @mirrorz/formats; (d) the Command/Mutation/inverse layer in @mirrorz/core with a private model and a commands-only mutation API. Nothing after this phase is safe to build without these four.
- PHASE 1 — SUBSTRATE (weeks 2–10). Layout index + axis RunStore + prefix sums, unit-tested against Excel's clamps (32,767 chars, 409 pt, 255 width). The chunked columnar cell store + StringPool + StyleTable with a memory test asserting 10M synthetic cells under 400 MB. The canvas grid painting a SYNTHETIC 1M×16K sheet with frozen panes at 60 fps — before any file parsing exists, because if it is not smooth on synthetic data it will never be smooth on real data. Then blitting + the three-tier text cache, gated by a scripted scroll benchmark asserting p99 frame time under 16 ms. Then history with macro transactions. THEN, and only then, the xlsx streaming parser. Also in this phase: the ref-rewriting layer, because every subsequent feature stores A1 references outside the cell grid and structural edits go stale silently without it.
- PHASE 2 — READ EVERYTHING (weeks 8–20, overlapping). Format order by cost/value, deliberately NOT alphabetical: csv/tsv → xlsx/xlsm/xltx/xltm → ods (reuses the zip+SAX layer, days of work) → xlsb (reuses zip/OPC + the style model; adds only the BIFF12 varint framer and ~25 Brt decoders) → xls (the expensive one: CFB + BIFF8 + Continue-stitching + legacy encryption). Doing xlsb before xls is counterintuitive and correct — it shares 80% of its non-framing machinery with xlsx and validates the record-decoder abstractions before the hardest format. Alongside: MS-OFFCRYPTO read (standard + agile + RC4/XOR + automatic VelvetSweatshop with a visible badge and forced read-only), which nothing in the JS ecosystem does end-to-end and which converts 'cannot open my file' into a feature. Render from cached <v> values immediately and recalculate progressively in the background — never block first paint on a 500k-formula recalc.
- PHASE 3 — CALCULATE (weeks 12–32, parallel with Phase 2). T0 operators and coercion FIRST (they make every function right or wrong), then T1 ~50 functions, then T3 dynamic arrays — XLOOKUP/FILTER/SORT/UNIQUE/LET/LAMBDA are NOT deferred, because any file touched by Microsoft 365 in the last five years contains them and #NAME? on XLOOKUP is the single most visible way to look broken. Then T2, T4 financial, T5 long tail plus the ~38 compatibility aliases. The dependency graph, RangeVertex chaining, iterative Tarjan scheduling, spill fixpoint, and the numerics layer (15-significant-digit truncation and display rounding, cosmetic snap-to-zero, the 1900 leap-year bug) all land here. Gate: the cached-value oracle must report a coverage-by-function table, and that table — not a feature checklist — is the progress metric.
- PHASE 4 — EDIT AND SHIP FREE (weeks 20–40). Full grid editing and selection semantics, fill handle with custom lists, clipboard including paste special and text/html interop (the highest-leverage interop win — 'copy from Excel, paste in with formatting' working on day one), the number-format compiler, cell styling with theme colours, row/col sizing and autofit, freeze panes, merges, sheet management including grouped-sheet editing, defined names (schedule EARLY — print areas, autofilter, tables, DV lists and LAMBDA all bottom out in the name table), data validation with dropdowns, conditional formatting read+render for all 18 rule types, autofilter and multi-key sort, find/replace and Go To Special, text-to-columns and remove duplicates, hyperlinks, comments (BOTH legacy and threaded, written as one atomic triple), print setup and PDF export through ONE paginator shared with Page Break Preview. Plus the table-stakes items with zero marketing spend: dark mode, Ctrl+Shift+V, and pixel-smooth scrolling (Excel's highest-voted UserVoice request, unanswered for four years — the thesis statement for the whole product). Ship the free Reader tier here to start building the file-association habit.
- PHASE 5 — SIGN, DISTRIBUTE, SELL (weeks 32–44, mostly calendar not engineering). Apple Developer Program ($99/yr) → signed + notarized macOS, which unlocks auto-update (Squirrel.Mac requires a signature) and reliable safeStorage. Azure Artifact Signing Basic ($9.99/mo) → SmartScreen-clean Windows; START THE IDENTITY VALIDATION EARLY (1–20 business days, three document attempts, non-prorated billing) and note the constraint that individual developers must be US/Canada while organizations get a wider list — incorporate first if the certificate should carry a company name rather than a personal name and home state. GitHub Actions 3-job matrix (macos-latest arm64 building a UNIVERSAL dmg, windows-latest, ubuntu-latest) publishing draft Releases. Ed25519 offline licensing behind electronFuses. Polar as merchant of record. Then the paid tiers go live.
- PHASE 6 — THE DIFFERENTIATORS (weeks 40–64). Local version history, semantic diff with structural insertion detection, three-way merge. The formula inspector with root-cause search. The multi-line formula editor. Regex everywhere offline (Find/Replace, filters, validation, conditional formatting AND formulas — RE2 flavour, linear time, no catastrophic backtracking on user-supplied patterns over a million rows). A sandboxed local TypeScript automation runtime with a typed workbook API, no cloud and no licence gate — the direct answer to Python-in-Excel executing in Microsoft's cloud and Office Scripts being web-only — with every script running as ONE undoable transaction. Charts read+render (classic types first, then the chartex families every JS library drops). Sparklines. Sheet explorer with folders and fuzzy search, and a conditional-formatting rules manager with coalescing — the two cheapest, most screenshot-friendly delighters on the list.
- PHASE 7 — THE HARD REMAINDER (weeks 60–100+). Pivot tables in three separately-shippable stages: read+preserve+render the cached cells (~2 weeks, and already beats every JS competitor), then the in-memory engine over Int32Array shared-item indices with bitset filters (~6–8 weeks, unlocks live pivoting, expand/collapse and drill-down), then write (~6–8 weeks, and only with an Excel-in-the-loop validation harness — openpyxl, with a decade of experience, concluded the pivot spec is too under-specified to author from scratch, so budget accordingly). Chart write. VBA in its own staged track that must never sit on the critical path: (1) extract and preserve byte-for-byte with a read-only source viewer — MS-OVBA is plain-OSP and this alone beats every JS library; (2) parse to AST plus a pre-run compatibility report (green/amber/red) — the feature that distinguishes us from LibreOffice, whose defining failure is silent breakage; (3) a sandboxed interpreter for the common business-macro subset in a capability-gated utility process, GATED on counsel's read of the [MS-VBAL] special terms. Explicitly out of scope and stated publicly in a per-feature compatibility matrix: UserForms (MS-OFORMS plus a whole control toolkit — the thing that killed LibreOffice's compatibility story), ActiveX/COM, Win32 Declare, and p-code execution.

## Risks

- SCOPE IS THE EXISTENTIAL RISK, NOT ANY SINGLE FEATURE. Excel is 40 years of accretion — 500+ functions, pivots, charts, Power Query, slicers, VBA, Copilot — backed by a team we cannot outspend, and every quarter spent chasing parity is a quarter not spent on the integrity axis where Excel structurally cannot follow (its undo model, its cloud-tied history and its format-baked grid ceiling are all frozen by backward compatibility). MITIGATION: define 'sufficient parity' explicitly and in writing, defend that line, and hold the five differentiators as the roadmap's spine. A per-feature compatibility matrix published as product documentation is worth more to a paying customer than an optimistic 'we support VBA'.
- THE [MS-VBAL] SPECIAL TERMS ARE UNRESOLVED AND SIT DIRECTLY ON THE VBA-EXECUTION MILESTONE. The Community Promise places the VBA Language Specification in a 'Covered Specifications with Special Terms' table — one of only two entries — with terms published on the document's own download page rather than on the promise page. Note the asymmetry that makes this easy to miss: [MS-OVBA], the file-format container, is plain-OSP with no special terms, so extraction and round-tripping will proceed smoothly and create a false sense that execution is equally clear. MITIGATION: download the current MS-VBAL and have counsel read the terms BEFORE writing interpreter code; budget for the answer being 'contact iplg@microsoft.com'; sequence VBA execution as a separately-gated milestone that can be cut without touching anything else.
- ACCIDENTAL COPYLEFT CONTAMINATION, WITH TWO SPECIFIC HIGH-PROBABILITY VECTORS: a developer stuck on a formula edge case opening LibreOffice's sc/, and a developer reaching for HyperFormula because it is TypeScript-native and one npm command away. The second is worse than a normal violation because HyperFormula enforces at runtime — an accidental dependency writes #LIC! errors into users' cells. MITIGATION: the CI licence scanner with a named denylist, a written clean-room rule (whoever reads a copyleft implementation to understand an algorithm does not write our version of it), spec citations in every parser PR, and a CONTRIBUTING requirement to declare consulted references. This is cheap now and unreconstructable at acquisition-diligence time.
- APTOS IS A COMPOUNDING, UNFIXED FIDELITY BUG. Microsoft replaced Calibri with Aptos as the Office default in 2023–24; it is proprietary, ships only with Microsoft 365, and — unlike Calibri, which got Carlito — has NO free metric-compatible clone. So the share of incoming workbooks specifying a font we cannot ship rises every quarter, and on macOS and Linux we will substitute at different widths and produce wrong column autofit, wrong row heights, wrong wrap points and wrong pagination versus Excel. MITIGATION: use system-installed Aptos on Windows when present (using an installed font is fine, redistributing never is); ship an explicit substitution table plus cached real metrics elsewhere; seriously consider commissioning or co-funding a metric-compatible substitute — it is an unfilled gap every non-Microsoft office suite now shares, so the cost is plausibly shareable.
- OUR OWN SPEC-COMPLIANT VBA WRITER PRODUCES MALWARE-SHAPED FILES. MS-OVBA tells us to drop p-code, set MODULEOFFSET=0, remove __SRP_* streams and truncate _VBA_PROJECT to its 7-byte header on write — which is byte-for-byte what the OfficePurge evasion tool does, and Mandiant published YARA rules matching a 7-byte _VBA_PROJECT. Files our users save may be flagged by AV/EDR at customer sites. This is a launch-blocking COMMERCIAL risk, not a technical one. MITIGATION: keep _VBA_PROJECT and PROJECT as close to the original as the spec permits, never emit the OfficePurge constant header, VirusTotal-test every release, and pre-emptively file false-positive reports with major vendors before launch.
- PERFORMANCE IS A PARITY FEATURE AND IT IS DECIDED IN WEEK ONE. Users hit walls at 100k–500k rows, far below the 1,048,576 ceiling, and 'slow and crashes on large files' is the most consistent complaint about every free Excel alternative. The specific traps: a Map-keyed or nested-object cell store (>1 GB at 10M cells, GC pauses during scroll), whole-column formatting materializing 1,048,576 records, unbounded devicePixelRatio quadrupling every blit, hidden columns iterated linearly, and forcing a full recalc before first paint. MITIGATION: stated, CI-gated budgets from the start — 50 MB xlsx to first painted cell under 3s, 1M formula cells recalculated under 5s, p95 scroll frame under 16ms, peak RSS under 1.5 GB — and publish the numbers, because 'opens the file Excel chokes on' is better advertising than any feature list.
- SILENT REFERENCE ROT WHEN STRUCTURAL EDITING SHIPS. Conditional-format sqrefs, data-validation sqrefs and formulas, chart <c:f>, pivot locations and worksheetSource all encode A1 references OUTSIDE the cell grid — and the ones we merely PRESERVE as opaque XML cannot shift themselves. Byte-preservation makes a read-only viewer trustworthy and makes an editor subtly, invisibly wrong. MITIGATION: build the ref-rewriting layer before the first insert-row command, and where a part is unmodelled, either parse enough to rewrite it or refuse the structural edit with a visible reason. Never shift cells while leaving preserved sqrefs pointing at the old range.
- EXCEL'S FAILURE MODE FOR OUR WRITER IS SILENT DELETION, NOT AN ERROR. 'We found a problem with some content' strips the offending feature and reports nothing useful; the dominant causes are an out-of-sequence child element (OOXML uses xs:sequence — exceljs ships this exact bug today, emitting legacyDrawing after extLst) and a count attribute disagreeing with its child count. LibreOffice does not catch either, so a LibreOffice-only test loop passes green while real Excel quietly eats every pivot table we write. MITIGATION: schema-order tables as generated DATA with a serializer physically incapable of appending, a pre-save referential-integrity validator, and an Excel-in-the-loop corpus (which this repo currently lacks entirely — every fixture is openpyxl- or LibreOffice-authored).
- DYNAMIC-ARRAY METADATA REFERENTIAL INTEGRITY. A cell with cm="1" indexes into xl/metadata.xml; if that part is missing or the index is out of range Excel declares the workbook corrupt — EPPlus #459 is a confirmed real instance where a worksheet copy preserved cm attributes but not metadata.xml. Any cell-copy, sheet-copy or delete path must carry the metadata records or clear cm/vm. Non-optional in 2026 because dynamic arrays are ubiquitous in real files. Related: modern function names are STORED prefixed (_xlfn.UNIQUE, _xlfn._xlws.FILTER, _xlpm. for LAMBDA params); write them unprefixed and Excel rejects the file, read them without stripping and every modern function shows #NAME?.
- SHAREDARRAYBUFFER IS UNAVAILABLE UNDER file://, WHICH SILENTLY DISABLES THE ENTIRE ZERO-COPY DESIGN. Electron's loadFile() cannot carry COOP/COEP headers (electron#31789), so SharedArrayBuffer is simply undefined and WASM-threads modules fail. And COEP:require-corp then blocks any cross-origin subresource, breaking embedded remote iframes/webviews for a hosted help page or a checkout flow. MITIGATION: serve the renderer from a privileged custom scheme, assert self.crossOriginIsolated in CI, keep the postMessage path behind the same interface as a fallback, and put any remote content in separate BrowserWindows.
- OPENING UNTRUSTED FILES FROM EMAIL IS A REAL ATTACK SURFACE, AND WE ARE OPENING BINARY FORMATS WITH A CVE HISTORY. libxls accumulated a long list of memory-safety CVEs precisely in BIFF record parsing (heap overflows on malformed cb, OOB reads on MulRk/MulBlank counts, SST index overruns), and xlrd's maintainers DELETED xlsx support rather than harden the zip+XML surface. MITIGATION: never trust a length or index from the file (bound cb, cch, cRun, isst, ixfe, MulRk counts, FAT chains, directory entries); zip-bomb, entry-count, ratio and path-traversal caps; XML entity expansion disabled; parsers in a utilityProcess with no filesystem or network at the OS level; a fuzzing job from day one seeded with the libxls and calamine corpora.
- THE ELECTRON LGPL COMPLIANCE CHORE ATTACHES TO SHIPPING THE INSTALLER, NOT TO ANY CODE WE WRITE — which is exactly why it goes unnoticed until an enterprise procurement review asks. Electron's prebuilt binaries bundle FFmpeg under LGPL-2.1 and electron#34236 documents that corresponding source is not published alongside the releases. MITIGATION: evaluate shipping Electron's ffmpeg-free build (a spreadsheet has no use for FFmpeg, and this deletes the obligation outright); otherwise host the exact matching FFmpeg source per release or publish a written three-year offer, generate a complete third-party-licences document at build time, and RECORD which half of every OR-dual dependency we elected — 'you get to choose' only protects us if the choice is written down.
- SEVERAL RESEARCH INPUTS COULD NOT BE VERIFIED FIRST-HAND BECAUSE THE RESEARCH ENVIRONMENT'S EGRESS PROXY BLOCKED THE PRIMARY SOURCES: decisionmodels.com and support.microsoft.com (Excel's floating-point and cosmetic-rounding rules), learn.microsoft.com for some pages, ecma-international.org and iso.org (the free-standard download URLs), reddit/MrExcel/TechCommunity (the UserVoice vote-count framing), kohei.us (mdds internals) and the Google Docs canvas write-ups. MITIGATION: derive the numeric rules EMPIRICALLY from Excel-generated fixtures rather than from any quoted threshold, and re-verify anything that goes into a pitch deck, investor material or public claim against the primary source from an unrestricted network before publishing it.

## Test strategy

- LAYER 1 — THE CACHED-VALUE ORACLE (build this before writing more of the formula engine; it will change what you build next). Every Excel-written .xlsx carries <c><f>SUM(A1:A9)</f><v>45</v></c> — ISO/IEC 29500 defines <v> as 'the cached formula value based on the last time the formula was calculated' — which is a free, labelled (formula, expected) test set at a scale nobody could author by hand. Iterate every formula cell in the corpus and assert our evaluation reproduces the cached value. THREE MANDATORY FILTERS or it is noise instead of signal: skip workbooks with calcPr/@fullCalcOnLoad (Excel itself distrusts those values), skip workbooks whose docProps/app.xml <Application> is not Microsoft Excel (openpyxl, LibreOffice and server generators omit or stale <v>), and skip volatile functions and their dependents (NOW, TODAY, RAND, RANDBETWEEN, OFFSET, INDIRECT, CELL, INFO). Comparison must use Excel's 15-significant-digit semantics (relative epsilon ~1e-13 plus an exact-zero case), and error values compared as exact strings. OUTPUT A COVERAGE-BY-FUNCTION TABLE from every run — that table, not a feature checklist, is the real progress metric toward 'runs Excel formulas'.
- LAYER 2 — PRESERVATION AND ROUND-TRIP. Open → no-op → save must leave the zip entry SET unchanged and every retained part XML-semantically equal; any diff is a bug. Assert semantic equality of a normalized model for read→write, and separately assert GENERATION-2 BYTE IDEMPOTENCE — write(read(write(read(f)))) === write(read(f)) — which is the invariant that actually catches writer bugs. NEVER assert byte equality against the original file: zip entry ordering, sharedStrings dedup, style renumbering and calcChain regeneration all differ legitimately. Corpus must exercise pivot tables + pivotCache, classic charts AND chartex, drawings + images, legacy comments + threaded comments + persons.xml, data validation (inline and x14), every CF rule type including databars and icon sets that live in extLst, tables/tableParts, defined names including _xlnm.*, hyperlinks, external links, dynamic arrays + metadata.xml, a Strict-conformance file, a 1904-date file, and a macro-enabled workbook.
- LAYER 3 — CROSS-IMPLEMENTATION DIFFERENTIAL TESTING. Run the same corpus through Apache POI (Apache-2.0), SheetJS CE (Apache-2.0), calamine (MIT), LibreOffice headless (`soffice --headless --convert-to csv:...` with the evaluate-values flag) and Gnumeric — all as SUBPROCESSES, never as linked code, because black-box use of a GPL program creates no derivative work while copying one line does. Where three agree and we differ, we have a bug; where all four differ, we have found a genuine spec ambiguity worth documenting. LibreOffice is a TIE-BREAKER for cells the cached-value oracle already flagged, not a general oracle — it deliberately diverges on the 1900 leap-year bug, RAND, several financial functions and array spill semantics, and this repo's docs/oracle-divergences.md is already the right place to record every such disagreement (it must grow a row for every case where the oracle, the spec and real Excel disagree, and it already correctly notes that LibreOffice returns #NAME? for XLOOKUP/XMATCH, so those expected values are hand-specified and need real-Excel verification).
- LAYER 4 — THE EXCEL-IN-THE-LOOP LOOP (the gap this repo has today). Every current fixture is openpyxl- or LibreOffice-authored, which is excellent ADVERSARIAL input (no numCaches, default namespaces, junk attributes, both boolean spellings) but is not the thing we must be bit-compatible with. Stand up a Windows box or VM that: generates adversarial fixtures (arithmetic edge cases, all 15-digit boundaries, date serials 0/59/60/61, the full coercion matrix, every error propagating through every operator, spill collisions, implicit intersection in both modes, R1C1 round-trips), opens them in real Excel, saves, and captures the cached <v> values as committed expectations. Then run the inverse: open OUR output in Excel, save from Excel, and diff Excel's output against our input — anything Excel rewrote or dropped is a place our writer was wrong or our model was lossy. 'It opened in Excel' is NOT proof of correctness. This loop is mandatory before pivot write or chart write ships, because Excel's failure mode is silent repair, not a useful error.
- LAYER 5 — PROPERTY-BASED TESTING (fast-check). Target the algebraic laws, because the shrinker turning a 5,000-cell random failure into a two-cell repro is the entire value: A1↔R1C1 round-trip, parse(serialize(ast)) === ast, reference translation under insert-row-then-delete-row is the identity, range union/intersection commutativity, SUM order-insensitivity within tolerance, style interning is injective, and — the highest-value one — random EDIT SEQUENCES against a naive full-recalc reference implementation, which is the only way to catch dirty-propagation bugs, since those are silent and catastrophic. Also property-test the MS-OVBA codec (compress→decompress→identity) and the undo layer (apply N random commands, undo N times, assert the model is byte-identical to the start state).
- LAYER 6 — HEADLESS STATE-MACHINE SUITES (no DOM, no canvas). The selection model, the fill-handle series detection, the merge-interaction matrix (merge × {navigate, Ctrl+Arrow, sort, filter, insert, delete, paste, CF, DV, print}), and the undo/redo stack are all pure state machines and should be tested as such. This is the highest-ROI test asset in the project because these are the semantics you cannot borrow from any OSS grid, and a DOM-free suite runs in milliseconds so it can gate every commit.
- LAYER 7 — E2E VIA PLAYWRIGHT `_electron` (run under xvfb-run on Linux CI). The unique advantage over Tauri: `electronApp.evaluate()` executes in the MAIN process, so we can drive the three file-association code paths directly — argv cold start via electron.launch({args:['out/main.js','fixtures/basic.xlsx']}), macOS cold start via app.emit('open-file'), and warm start via second-instance — plus the license state machine, the trial clock, and crash recovery. Also assert self.crossOriginIsolated === true at boot and fail the build if not, because losing cross-origin isolation silently disables the entire SharedArrayBuffer design.
- LAYER 8 — FUZZING AND HOSTILE INPUT. Run SheetJS/enron_xls (~16,189 real de-duplicated spreadsheets, including the .xls-that-is-actually-HTML/TSV/SYLK cases users genuinely double-click) as a does-not-crash / does-not-hang / produces-a-diagnosable-error gate with per-file timeouts. Store only hashes and expected outcomes in the repo; download the corpus in CI. Seed a continuous fuzzer from the libxls /fuzz and calamine /tests corpora against the CFB reader, BIFF8 scanner, XLSB varint framer, ZIP reader and XML parser — every libxls CVE was a length or index trusted from the file, and we will be opening email attachments on end-user desktops.
- LAYER 9 — PERFORMANCE AND MEMORY AS GATES, NOT ASPIRATIONS. `vitest bench` micro-benchmarks with baselines checked into the repo, failing CI on >10% regression using a 3-run median to absorb runner noise. Four macro budgets measured through Playwright with performance.now() marks: cold open of a 50 MB xlsx to first painted cell <3s; full recalc of 1M formula cells <5s; p95 scroll frame time <16ms over a 1M-row sheet; peak RSS on the 50 MB file <1.5 GB. Plus a standalone memory test asserting 10M synthetic cells stay under 400 MB heap. Publish these numbers on the marketing site — having them in CI means we cannot regress the claim.
- LAYER 10 — VISUAL AND LEGAL GATES. Golden-image render tests at ±1px tolerance for number formats, autofit widths, conditional-format visuals (data bars, icon sets, colour scales) and print pagination — equality assertions will never pass against Excel's font metrics, so tolerance-based golden images are the only honest approach. A licence scanner over the full transitive tree with the hard-fail denylist. A font-binary hash check rejecting any ClearType/Monotype file. A grep over marketing copy and the app bundle enforcing that 'Excel'/'Microsoft'/'Office' appear only adjectivally before a generic noun. And a build-time third-party-licences document, surfaced in Help → Licences and in the installer, that fails the build if any dependency's licence text is missing.

## Dependency policy

Allowed:

- Runtime, permissive and vetted: electron (MIT; Chromium BSD-3 — but see the bundled-FFmpeg LGPL chore in risks)
- fflate (MIT) — DEFLATE/zip; preferred over JSZip on speed, which matters for large-workbook open times
- fast-xml-parser (MIT) — with entity expansion and external entities disabled
- iconv-lite (MIT) — MBCS/codepage decode for BIFF5/7 Label records and VBA PROJECTCODEPAGE
- d3-scale, d3-array, d3-shape, d3-hierarchy (ISC) — scales, ticks, arcs, curves, treemap/partition layouts inside our own canvas chart renderer
- echarts (Apache-2.0) — lazily code-split FALLBACK renderer for exotic chartex families only, behind a feature flag, deletable
- node:crypto (Node 24 built-in) — Ed25519 license verification and all MS-OFFCRYPTO key derivation. No third-party crypto library ships in the binary
- Fonts, bundled: Carlito, Caladea, Liberation Sans/Serif/Mono, DejaVu (SIL OFL 1.1) — metric-compatible substitutes for Calibri, Cambria, Arial, Times New Roman, Courier New. Ship the OFL text; RENAME any font we modify (Reserved Font Name)
- Icons, bundled: Lucide (ISC) OR Phosphor/Tabler/Bootstrap Icons (MIT) OR Material Symbols (Apache-2.0) — pick exactly ONE family and commit
- Vendor/port with attribution + NOTICE (source-level reuse, not runtime deps): SheetJS Community Edition (Apache-2.0 — bits/10_ssf number-format engine, 18_cfb, 59_vba, 44_offcrypto; take from cdn.sheetjs.com with a pinned hash, NOT the frozen npm package)
- Apache POI / NPOI (Apache-2.0) — the behavioural oracle and a legally portable source for POIFS/CFB, HSSF BIFF record definitions, DataFormatter, and formula-evaluator semantics. Apache-2.0→Apache-2.0 is the only zero-friction inbound licence we have
- Univer @univerjs/* core packages ONLY (Apache-2.0) — the Command/Operation/Mutation model, the render-skeleton/viewport design, packages/core serial-date.ts, and the sheets-conditional-formatting / sheets-data-validation layering

- calamine (MIT) — reference and benchmark baseline for xls/xlsb, and the seed if Rust/napi is ever justified
- xlsx-populate (MIT) — the preserve-unknown-parts thesis (architecture, not code)

Refused:

- HyperFormula — GPL-3.0-only OR paid proprietary, from Handsoncode. The most tempting trap in the project: TypeScript-native, npm-installable, and it solves our hardest problem. One `npm i` puts an Apache-2.0 product we sell in violation, GPLv3's conveyance and installation-information terms are irreconcilable with a signed auto-updating binary, and it ENFORCES AT RUNTIME by writing a #LIC! ErrorType into user cells without a key. Do not install even 'temporarily'; do not read the source with intent to reimplement.
- Handsontable v7+ — proprietary, free only for 'strictly personal or solely for evaluation purposes', AND carrying an explicit anti-competition clause: 'you must not make any such use of this software as to develop software which may be considered competitive with this software.' A spreadsheet app is exactly that, so even EVALUATING it while building this arguably breaches the free-use terms.
- ONLYOFFICE sdkjs — AGPL-3.0. Viral into an Apache-2.0 codebase, and §13's network clause additionally poisons any future cloud/sync tier — the very thing that would justify a subscription. Do not vendor, link, shell out to, or bundle as a converter sidecar.
- Gnumeric — GPL-2.0/GPL-3.0. Best free documentation of Excel's numerical quirks and therefore maximally tempting; no reading-then-writing. Use only as a black-box test oracle.
- LibreOffice / Collabora core (sc/, oox/, chart2) — MPL-2.0 project policy with substantial LGPLv3+ legacy and a GPLv3 COPYING at repo root; per-file reality binds and no single snapshot is the truth. MPL's file-level copyleft would drop an MPL file with disclosure duties inside our product; LGPLv3's anti-tivoization and relinking terms are actively hostile to a code-signed notarized binary. Already used correctly in this repo as a headless fixture oracle — keep it strictly there.
- EPPlus 5+ — Polyform Noncommercial 1.0.0. WORSE than GPL for us: commercial use is prohibited with no compliance path short of purchase. Its ChartEx namespace is one of the only complete chartex object models anywhere, which is exactly why an engineer searching for chartex examples will land on it. API docs fine; source never. (EPPlus 4.x LGPL is also unusable.)
- ag-grid-enterprise and @ag-grid-enterprise/* — commercial EULA living in the SAME repo as the MIT community packages, so a developer studying virtualization can read EULA-covered source without noticing a boundary. Every spreadsheet-shaped feature (range selection, fill handle, clipboard ranges, pivoting) is on the enterprise side, so the natural path is a slow slide into paid territory discovered at build time.
- @univerjs-pro/* — NO licence field on npm at all, i.e. all rights reserved, and it differs from the Apache-2.0 @univerjs/* by one hyphen. Treat a missing licence field as a HARDER failure than an explicit copyleft one, because it reads as nothing.
- NocoDB — 'Sustainable Use License', not OSI open source: internal-business/non-commercial only, redistribution only free of charge. 64.8k stars makes it a magnet for contributors who assume popular means permissive.
- Quadratic — Quadratic Source Available License (no distribution of derivatives, no business deployment without a commercial licence), and the main repo went private in 2026. Read the public blog for the worker-topology idea; never the code.
- XLParser — MPL-2.0. The published academic grammar paper is the normative artifact and is what we implement from; a C#→TypeScript port of ExcelFormulaGrammar.cs IS a derivative work. Use the binary as an external differential oracle only.
- pcodedmp and Rubberduck — GPL-3.0. Rubberduck has the most complete open VBA grammar in existence and is therefore the most dangerous thing to read while writing ours; implement from [MS-VBAL] and keep a written record that we did.
- Keygen server code (keygen-api) — FCL-1.0-ALv2 (Fair Core License), NOT Elastic License 2.0 as many 2026 posts still claim. Using Keygen Cloud or self-hosting CE is permitted; vendoring its server code into this repo is not, and it forbids circumventing its own key check. Moot anyway: our client-side Ed25519 verification is ~15 dependency-free lines.
- Flexmonster / WebDataRocks — proprietary, and the MIT React wrapper around a proprietary core is the pattern to watch for. Neither speaks pivotCacheDefinition, so neither could write a valid xlsx pivot part regardless.
- npm `xlsx@0.18.5` — frozen and deprecated (SheetJS left the registry in 2023 for cdn.sheetjs.com), carrying CVE-2023-30533 (prototype pollution) and CVE-2024-22363 (ReDoS) with no upgrade path via npm. Any SCA/SBOM scan on a commercial product flags it and there is no remediation. Vendor reviewed Apache-2.0 CE source instead.
- EtherCalc / SocialCalc — a four-licence mix including CPAL, an AGPL-style network copyleft WITH an attribution-badge requirement forcing the original author's branding into our UI. Flatly incompatible with a white-label commercial product and easy to miss because the README leads with the MIT and CC0 portions.
- Font Awesome Free (avoid by preference, not a hard block) — icons are CC BY 4.0, imposing an ongoing attribution duty on the icons themselves for zero benefit over ISC/MIT alternatives. Hard-block @fortawesome/*-pro, which installs from a private registry and lets a developer's personal subscription contaminate the build.
- Any font binary extracted from a Windows or Office install — Calibri, Cambria, APTOS, Arial, Times New Roman. Never in the repo, a build image, a Docker layer, a CI cache, an installer or a test fixture. Trivially provable by hash and it survives in git history. Add a hash check to CI.
- Any Microsoft binary as a reverse-engineering target — excel.exe, VBE7.DLL, MSO.DLL. The Office EULA's no-decompile clause binds us as licensees independently of copyright, patent and the OSP. Running Excel and observing its outputs is a different activity and is fine and necessary; looking inside the binary is never.
- Anything GPL-*, LGPL-*, AGPL-*, SSPL, BUSL, CC-BY-NC, 'Sustainable Use', 'Source Available', UNLICENSED, or with a null/missing licence field — enforced as a hard CI failure across the transitive tree, not as a convention.
